## Verification and limits

Make preflight assertions control the command's exit status. A compound Docker
probe ended in a success message, masking possible earlier assertion failures.
Enforce `set -e` or explicit conditional exits inside the container shell, then
preserve the actual output and exit. Rechecking the frozen images confirmed the
expected runtime; the defect was in the observation method, not installation.

Check observation freshness before interpreting a quiet log as idle execution.
The benchmark's stdout filtering pipeline can buffer events, so its last visible
assistant-start event does not establish that the assistant is still generating.
Use native session timestamps and completed tool records to assess intervals;
distinguish unknown provider/generation time from gaps in log delivery. Do not
infer a reasoning loop from absent live output.

Reusing a frozen profile proves input identity, not compliance with the current
campaign protocol. Before admitting it, check effective instruction metadata as
well as settings. An inherited solver skill still said "Must always apply" despite
the solver-specific exception. Preserve the old artifact and charge, record the
qualification correction, and reject that metadata in the next launcher. Keep
orchestrator policy unchanged; do not infer a runtime role from the benchmark's
task scope. A negative check against the inherited copy and a positive check
against the corrected isolated copy cover this failure without model calls.

Keep the active checklist authoritative when the user retires an experiment family. Remove its pending variants from the queue, preserve unfavorable evidence, and distinguish a user-directed exclusion from proof that every component is harmful. Completion of one requested experiment is a decision checkpoint, not an automatic stop when the user has authorized continued exploration.

Qualify stateful tracking tools before measuring their effect on prioritization. The upstream TODO example returned shallow snapshots and restored their objects by reference; toggling an item changed earlier live session history while the saved JSONL retained the original value. A private copy fixed this by copying scalar task objects at both boundaries. The useful regression compares actual CLI live history with durable history, then exercises restart and immediate mutation after reconstruction. Scripted provider fixtures prove state and transport behavior, not model focus or performance. Keep local workflow grades separate from official benchmark scores.

Evaluate tools and settings for their intended task horizon. Bounded tasks can measure overhead while missing benefits during sustained work. When minimal overhead is acceptable to the user, lack of a speedup does not justify removal; require relevant evidence of worse sustained focus, completion, recovery or required verification against a valid baseline. Preserve correctness and state-integrity checks. Distinguish provisional retention with unproven benefit from a demonstrated gain. Record actual calls, context use and unfinished obligations; elapsed compilation time alone is not a long-context test. Check existing configuration before building automatic activation, whose complexity can cost more than small overhead. Schema characters are not a token or latency measurement.

Shorter instructions need semantic review as well as size checks. Compression can
broaden a restriction accidentally: a rule about search/fetch providers must not
become a prohibition on all hosted services. Map retained obligations before
freezing a candidate, verify the actual delivered prompt, and compare initial
input separately from whole-task calls and tokens. A smaller initial context did
not consistently reduce total work in matched trials. Equal test counts also hid
different exercised paths; inspect coverage rather than assuming equivalence.
Describe how to discover mutable configuration instead of copying enabled states
or model defaults into prose that can become stale.
Report constraint compliance and smaller context separately from task quality.
A proxy improvement does not outweigh adverse end-to-end results. Check whether
verification assertions propagate failure; an unconditional success message and
a zero final shell exit can conceal an earlier failed assertion.

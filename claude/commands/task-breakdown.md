Break down the following into smaller tasks: $ARGUMENTS

## Step 1: Understand the Feature
- What is the end goal?
- Who is the user/consumer?
- What are the acceptance criteria?

## Step 2: Identify Components
- What parts of the codebase are affected?
- What new code needs to be written?
- What existing code needs to change?

## Step 3: Create Task List

Break into small, independently testable tasks:

### Task 1: [Name]
- **Description**: What exactly needs to be done
- **Files**: Which files will be touched
- **Dependencies**: What must be done first
- **Testable**: How to verify it works

### Task 2: [Name]
...

## Step 4: Order Tasks
1. List tasks in implementation order
2. Identify what can be done in parallel
3. Note any blockers or questions

## Guidelines
- Each task should be completable in one focused session
- Each task should be testable on its own
- Avoid tasks that touch too many files
- Prefer vertical slices (end-to-end) over horizontal layers

## Questions
List any clarifications needed before starting.

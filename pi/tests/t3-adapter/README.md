# T3 adapter proof

This is an incomplete adapter checkpoint, not ready for deployment. Nested coordinators and deterministic native `/arena` have protocol-fixture coverage. Native-host parity verification and completed-child same-thread resume still block release. The published controls checkpoint refuses completed assignments rather than silently substituting a fresh child conversation.

Run `bash pi/test-t3-adapter.sh` to test a freshly applied repository package patch against the installed CLI. An optional package-root argument selects an already-applied private package; a second argument selects a verified private CLI with the repository readiness patch. The runner uses isolated HOME, synthetic credentials and loopback servers. It does not deploy or change T3.

`runtime.mjs` launches the real Pi CLI with `--t3 --team`, sends readonly `get_state`, then races a prompt ahead of any parent binding. It requires refusal of that original RPC command with zero provider requests. `leaf.mjs` launches real parent and child RPC processes, delays the native delegation response to exercise the binding race, then checks the bound profile, TeamStore DM/reply IDs and root audit, non-deliverability before native terminal status, eventual retirement while the child process remains alive, idle parent eligibility, no revival, and root restart refusal.

The fixtures model authenticated T3 `thread_list`, `thread_read`, `task_status` and nested native delegation. These are protocol tests, not live T3 application tests. The initial RED failed with `Unknown option: --t3`; both fixtures passed on the private readiness runtime at the leaf checkpoint.

Evidence remains in the directory printed by the runner. Authorization headers are checked but never logged.

## Delivery and coordinator regressions

Run `bash pi/test-t3-adapter.sh '' <verified-private-cli> completion-ack` for the counterfactual native-delivery case. It models T3's terminal `task_status` acknowledgement suppressing a later native completion wake. The test requires the actual parent provider request to contain the completion, not merely a successful status response. This case failed with the background `task_status` observer. It now passes with child-authenticated `t3_thread_wait` targeting the exact bound run. The parent model receives native completion without a competing adapter notification. The original passing leaf fixture did not model this side effect and was insufficient for release.

The `wait-run-mismatch` and `observation-error` cases require uncertainty to remain non-deliverable and unknown, without claiming native completion. The `tool-fence` case reactivates `bash` through a fixture extension, then attempts nested execution from an allowed helper. It requires both an execution refusal and absence of `bash` in every subsequent provider request. This case caught a real declaration leak after the execution fence had correctly refused the tool. All discovery fixtures use the public `t3_thread_*` tool names rather than internal service method names.

Run the same command with `coordinator` as the last argument for the nested coordinator case. It requires a permitted coordinator to launch a leaf, remain available for its question, receive native completion steering, consume results, and synthesize before its single final settlement. `inline-correction`, `overflow`, `decline` and `abort` cover one actionable correction, results beyond the native inline budget, honest native interruption after refusal, and cancellation of a held coordinator without model keepalive calls. The status fixture uses actual-host-shaped direct task JSON in `content[0].text`, without a synthetic `structuredContent` envelope. Decoding also accepts the envelope retained by some nested execution results. `status-error` and `status-wrong-run` prove that errors and mismatched native runs do not discharge an obligation. Success asserts `agent_settled.aborted === false`, not merely a synthesis string followed by settlement.

`arena`, `arena-off`, `arena-cancel`, `arena-dropout` and `arena-delayed` exercise the registered command through scoped command tool execution. They create independent candidate files and rationales, run one read-only cross-judge after candidates finish, read the candidates in the coordinator, write synthesis and rejection/dropout notes, and verify the artifact through a real tool. Normal team messaging stays suspended, ON/OFF is restored, and cancellation goes through the native tool rather than process signals. The fixture does not substitute a model request for command execution. `arena-delayed` withholds native notifications until explicit consumption, reproducing candidates and judge completing in separate cohorts. Each task gets one actionable correction, not one correction shared across the entire arena lifetime. Refusing the same corrected result still interrupts rather than looping.

## First-slice boundaries

This checkpoint covers local native Pi profile threads, nested coordinators and deterministic arena. An ordinary root provider-process replacement can rejoin after the lifecycle guard owns the same canonical saved file. The immutable root claim is not deleted, saved OFF wins over `--team`, the root gets a new incarnation, and completed descendants stay retired. `root-resume` exercises the native fresh-process `switch_session` sequence with the real guard. Changing an already-admitted thread to an unrelated session/fork and restarting a completed child remain explicit refusals. Terminal tmux delegation must remain unchanged. `--t3` selects native launch; `--team` independently selects messaging.

Admission must bind exact native task, child-thread and run IDs to a trusted local profile before inference. Neither task prose nor `orchestrator_capabilities.parentThreadId` supplies child lineage. The unbound RPC case exercises `get_entries` and model/thinking/name setup before binding, checks that these native startup operations succeed, and verifies zero provider calls. The first execution request waits for binding and applies profile/request model and thinking defaults once. Later acknowledged native selections remain authoritative. The `metadata` case changes model/thinking while a coordinator is held and checks every later provider request plus saved selection history; tool and child permissions remain fixed. Cache warming is stopped while unbound, stopped or settled. RPC readiness does not globally fence arbitrary autonomous work from trusted extensions; that is outside this adapter's supported boundary. The native readiness capability must be detected before recognizing `--t3`; registering an unknown event is not enforcement.

Only a delegated leaf becomes non-deliverable at `agent_settled`. The hook must return without waiting for native terminal status. An idle parent remains eligible. Native terminal observation occurs outside that hook through child-authenticated self `t3_thread_wait`, constrained to the exact bound run. `task_status` and parent reads of child terminal output are not background observation APIs because they can acknowledge completion delivery. Observation failure leaves the leaf non-deliverable with unknown status, never completed or re-admitted. A live idle provider process is not proof of a live task.

T3 owns process launch and cancellation. Each process keeps independent saved-session ownership. Provider shutdown or reload cannot signal descendants or reuse `PI_LIFECYCLE_OWNER`.

`steer` verifies model-visible `subagent_message` reaches the exact live child run through nested native tool hooks. `question-off`, `question-suspended` and `question-permission` exercise native user-input UI, exact owned request answering, independence from normal messaging state, permission-request rejection, and stale-answer no-revival. The question record is protocol state in TeamStore; it does not grant permission approval.

Required remaining proof includes real-host parity behavior, same-thread completed assignment resumption with original history, inherited ownership rejection, and missing-capability/offline discovery controls. `alias-fence` proves canonical `mcp__t3_code__` names cannot bypass the active-wrapper guard through a nested helper. Team/tmux arena regressions passed after the coordinator checkpoint. The current fixture observes a real nested call ID, but does not establish the real T3 permission integration. A passing mocked protocol test does not establish live T3 GUI behavior. Use the repository real-host test when the coordinator implementation is ready.
